# Безопасность

Репозиторий приватный, но относитесь к нему как к публичному. **Учётных данных в нём нет.** Проверьте сами:

```bash
bash scripts/check-secrets.sh              # текущее дерево
bash scripts/check-secrets.sh --history    # все ревизии
```

`секретов не найдено` и код возврата 0 значат, что чисто. Скрипт ищет ключи Anthropic, OpenAI, GitHub, GitLab, Meta, Slack, AWS, Google,
приватные ключи PEM, JWT и строки подключения к базам, а также файлы, которых в репозитории быть не должно: `.env`, `.env.local`,
`*.pem`, `id_rsa`, `cookies.json`, `*.session`.

## Правила

- Секреты только в `.env.local` (в git не попадает) и в настройках Vercel.
- `SUPABASE_SERVICE_ROLE_KEY` даёт полный доступ к базе. Только на сервере (Vercel), никогда в браузерный код, чат или коммит.
- Публичные значения (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) безопасны для браузера, защита данных держится на политиках RLS в `studio/supabase/`.
  Не отключать RLS и не ослаблять политики без записи в `DECISIONS.md`.
- Агент не просит прислать пароль или ключ в чат. Владелец вставляет их сам.
- Персональные данные учеников (имена, телефоны, почты, оплаты) не коммитить, не выгружать в файлы репозитория.
- Ключ уже попал в коммит: сначала отозвать и выпустить новый, чистка истории потом.
- Переписывание опубликованной истории и force-push: отдельное решение владельца.

## Сторож стоит на трёх входах

1. Хук перед коммитом: `bash scripts/hooks/install.sh` (ставится при `bootstrap-portable.sh`).
2. GitHub Actions `secret-scan` на каждый push и pull request.
3. Ручной запуск скрипта.

Ложное срабатывание: допишите в конце строки комментарий `allow-secret`.
