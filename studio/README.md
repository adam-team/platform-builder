# Эксперт Аты-жөні — платформа

React + Vite + Supabase, деплой на Vercel. Бренд «Бренд атауы»: зелёный + Commissioner,
у каждого направления (қарыз/жинақ/үй/ипотека) свой цвет.

## Запуск с нуля (новый проект)

1. **Supabase** → New project. Затем SQL Editor → вставить `supabase/schema.sql` → Run.
2. **.env.local**: скопировать `.env.example`, вписать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`
   (Project Settings → API).
3. `npm install && npm run dev` → http://localhost:5173
4. Зарегистрироваться на платформе, затем в SQL Editor:
   `update public.profiles set role = 'admin' where email = 'ВАША_ПОЧТА';`
5. Supabase → Authentication → Sign In / Providers → Email → выключить Confirm email на время тестов.
6. Supabase → Authentication → URL Configuration: Site URL = адрес сайта на Vercel
   (и `http://localhost:5173` в Redirect URLs для разработки).

## Если schema.sql уже был выполнен раньше (наш случай)

Проект уже создан по старой схеме (общий каркас free/paid/admin). Чтобы получить всё для
Эксперт Аты-жөні, выполните в SQL Editor по очереди, каждый целиком:

1. **`supabase/migration_02_expert.sql`** — категории, услуги, настройки сайта, прогресс уроков.
2. **`supabase/migration_03_features.sql`** — списки преимуществ у курсов и услуг («Курс нәтижесінде сіз: …»).
3. **`supabase/migration_04_about.sql`** — блок «Эксперт туралы»: список фактов и история под кнопкой «Толығырақ».
4. **`supabase/migration_05_news_assignments_profile.sql`** — новости, задания с ответами учеников, телефон в профиле.
5. **`supabase/migration_06_answer_review.sql`** — отметка «Тексерілді» у ответов для «Жауаптар ленасы».
6. **`supabase/migration_07_support_chat.sql`** — чат «Сұрағыңыз бар ма? Кураторға жазыңыз» и «Хабарлар → Кіріс».
7. **`supabase/migration_08_site_blocks.sql`** — карточки целей на главной, интро/шаги страницы бесплатных
   уроков, блок о компании Brand, блок кейсов, финальный CTA — раньше это было зашито в коде, теперь
   редактируется из админки («Сайт → Басты бет / Тегін сабақтар / Қызметтер беті»).

Ничего не удаляют, только добавляют. Новый проект — все уже включены в `schema.sql`, отдельно запускать не нужно.

## Демо-режим (без Supabase)

```bash
VITE_DEMO=1 npm run dev
```

Три кнопки входа (админ/платный/бесплатный), вымышленные данные, сбрасываются при обновлении
страницы. Полезно, чтобы посмотреть дизайн без настройки базы.

## Деплой (Vercel)

Импортировать папку, в Environment Variables добавить:
`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (секрет, только тут).

Создание клиентов из админки идёт через `api/admin-create-user.ts`. Локально она работает только под `vercel dev`.

## Структура сайта

- `/` — главная (публичная, без входа): hero с фото, лента новостей, статистика, выбор цели, о Эксперт.
- `/courses`, `/course/:id` — каталог курсов по категориям и страница курса с программой.
- `/services` — разовые услуги (консультация, разбор, сопровождение).
- `/free-lessons` — тегін сабақтар, лид-магнит.
- `/lesson/:id` — урок: видео, вкладки Сипаттама/Материалдар/Тапсырма (тапсырма — с ответами учеников и
  комментариями куратора/платных клиентов).
- `/cabinet`, `/my-courses` — кабинет и список курсов платного клиента (только после входа).
- `/profile` — имя, телефон, смена почты и пароля (для платных клиентов и админа).
- `/admin` — админ-панель в стиле GetCourse (см. ниже).

На телефоне у платного клиента внизу 5 кнопок (Басты/Оқу/Қызметтер/Тегін/Профиль). У админа обычной клиентской
шапки/нижнего меню нет вообще — вход сразу открывает `/admin`, отдельный полноэкранный экран (см. ниже).
Если админ сам заходит на публичный сайт (ссылка «🌐 Сайтты көру» в профиль-меню), он видит тот же топбар,
что и клиенты, и рядом с аватаром — кнопку «Админка» с золотой рамкой, чтобы быстро вернуться в консоль.

Аватар (в шапке у клиентов, в самом верху рельса у админа) открывает выпадающее меню: Профиль,
Хабарландырулар (счётчик непрочитанных новостей, скрыт у админа), Парольді ауыстыру, Шығу; у админа там же —
«Төлемдерді растау» и «Сайтты көру».

У всех вошедших, кроме админа, внизу слева — плавающая кнопка «💬 Кураторға жазыңыз»: простой чат с
поддержкой. Админ отвечает в Админка → Хабарлар → Кіріс.

## Админ-панель (полноэкранная консоль в стиле GetCourse)

`/admin` — отдельный маршрут вне клиентского Layout: без топбара и нижнего меню, только сама консоль.
На компьютере рельс с иконками разделов занимает всю высоту экрана слева (как на реальном
kemelgroup.getcourse.ru — без отдельной шапки над рельсом), аватар — маленькой кнопкой в самом верху рельса,
рядом — список страниц открытого раздела, справа — сама страница. На телефоне рельс не помещается, поэтому
сверху обычная шапка (лого + аватар) и под ней плоский ряд вкладок со всеми страницами сразу.

Разделы — только те, что были нужны, без CRM, конструктора сайта и тарифов:

- **Сайт** → три страницы, чтобы форма не была одной длинной простынёй:
  — «Басты бет» — фото, hero-текст, «О Эксперт», статистика, 4 карточки целей, финальный CTA;
  — «Тегін сабақтар» — интро и 3 шага страницы `/free-lessons`, блок «Сіз:» и блок материалов;
  — «Қызметтер беті» — блок о компании Brand и блок кейсов на `/services` (сами услуги правятся
  в «Оқыту → Қызметтер»). Все текстовые блоки сайта теперь редактируются здесь — ничего не зашито в коде.
- **Оқыту** → Тренингтер, Қызметтер, Жауаптар ленасы — все ответы учеников на задания по всем курсам в одном
  месте, с фильтром по курсу и «тек тексерілмегендер», как в GetCourse.
- **Оқушылар** → Пайдаланушылар (создание клиентов, курсы, логин/пароль, роль), Статистика (сводка:
  сколько пользователей, курсов, выдач доступа, общая выручка, последние регистрации).
- **Хабарлар** → Кіріс (входящие от кнопки «Кураторға жазыңыз», список чатов по ученикам с ответом),
  Рассылкалар — по сути та же лента новостей: публикация появляется на главной и как счётчик в
  колокольчике у вошедших пользователей. Настоящей email/SMS-рассылки нет — для неё нужен отдельный
  сервис, см. «Что ещё не готово».
- **Сатылым** → Төлемдер — заявки на оплату с подтверждением и сводкой по выручке.

**Тренингтер устроены так же, как в GetCourse** — список курсов со ссылкой «Ашу →», а не всё на одной
форме. Клик по курсу открывает его карточку с двумя вкладками: «Мазмұны» (список уроков, «+ Сабақ қосу»,
клик по уроку или «Өзгерту» открывает форму редактирования того же урока — заголовок, YouTube-ссылка,
текст, задание, материалы) и «Баптаулар» (название, описание, цена, категория и остальные настройки самого
курса). «← Тренингтер» возвращает к списку.

Не стали переносить: CRM (доска заказов/задач, воронки), конструктор страниц сайта (блочный редактор),
тарифы и биллинг аккаунта, видео-библиотеку (у нас видео — через ссылку YouTube), раздел Apps — вы
явно попросили без этого.

## Как устроена защита

- Роли: `free`, `paid`, `admin` (`profiles.role`). `paid` ставится автоматически при выдаче доступа к курсу.
- Курсы, услуги, программа уроков и настройки сайта видны без входа (как у GetCourse) — это нужно
  для конверсии из рекламы. Ссылка на видео и текст урока лежат в `lesson_content`, их отдаёт только
  тем, у кого есть доступ (RLS + `can_view_lesson`); бесплатный урок — исключение, он открыт всем.
- Видео на странице урока — `youtube-nocookie.com` embed с `rel=0&modestbranding=1&iv_load_policy=3`:
  логотип, реклама и предложенные чужие видео максимально убраны. Сам ID видео нигде не лежит в
  исходном HTML (SPA, подгружается только после входа и проверки доступа через RLS) — обычный
  пользователь через «Просмотр кода страницы» ничего не найдёт. Но полностью убрать возможность достать
  ссылку через инструменты разработчика (DevTools) невозможно, пока видео физически хостится на
  YouTube — так устроен любой iframe-виджет, это не вопрос кода. Честно: технически подкованный платный
  клиент всё равно сможет найти ссылку. Для настоящей защиты (подписанные временные ссылки, без всякой
  возможности их скопировать) нужно переносить видео на специализированный хостинг — Kinescope / Bunny
  Stream / VdoCipher (VdoCipher ещё добавляет водяной знак с именем/почтой зрителя поверх видео).

## Оплата

Сейчас (вручную, через Kaspi): клиент жмёт «Оплатить» → создаётся заявка `payments` (pending) и
открывается ссылка Kaspi → админ подтверждает во вкладке «Сатылым → Төлемдер» (`confirm_payment`) →
курс открывается автоматически (роль `free`→`paid`, доступ к урокам — всё уже готово в БД, см.
`sync_role`/`confirm_payment` в `schema.sql`).

**Следующий шаг (обсуждали):** заменить ручное подтверждение на настоящий платёжный шлюз с оплатой
картой (Epay от Halyk Bank — рекомендация, самый распространённый в Казахстане, есть готовый checkout
и webhook). Для этого нужно оформить приём платежей у банка/провайдера — юрлицо (ИП или ТОО) обязательно,
это банковское требование, обойти кодом нельзя. Когда будут тестовые ключи от провайдера — добавляем
`api/{provider}-webhook.ts`, который по приходу вебхука будет вызывать тот же `confirm_payment` с
service_role — вся остальная автоматика (доступ, роль, личный кабинет) уже существует и трогать не надо.

Для услуг (`services`) заявка нигде не сохраняется — клиент просто открывает ссылку оплаты/WhatsApp.
Это подходит для разовых консультаций; если нужно видеть заявки в админке — добавим `service_requests`.

## Письма и коды

- **Сброс пароля** — теперь по коду, не по ссылке: `/forgot` → на почту приходит 6-значный код →
  `/reset-password` → код + новый пароль (`supabase.auth.verifyOtp` + `updateUser`). Код отправляет сам
  Supabase Auth, но чтобы в письме показывался именно код, нужно один раз поправить шаблон: Supabase →
  Authentication → Email Templates → **Reset Password** → добавить в текст `{{ .Token }}` (это и есть код).
  Приглашение админом (когда создаёте клиента без пароля) как было по ссылке — так и осталось, это
  отдельный шаблон **Invite user**, его не трогали.
- **«Вам открыт доступ к курсу»** — письмо клиенту, когда админ выдаёт доступ («Оқушылар → Пайдаланушылар
  → Курстар» или сразу при создании клиента). Это не Supabase Auth, а отдельная функция `api/notify-access.ts`
  через [Resend](https://resend.com) (нужен `RESEND_API_KEY` и `RESEND_FROM` в переменных окружения — см.
  `.env.example`). Письмо не отправится, если ключи не заданы, но сам доступ при этом всё равно откроется —
  это не блокирующая часть.
- **Регистрация** — подтверждение почты при обычной самостоятельной регистрации (`/register`) отправляет
  сам Supabase Auth (шаблон **Confirm signup**), отдельно ничего не делали.
- SMS не подключали (обсуждали — решили пока только email, SMS в Казахстане платный за каждое сообщение,
  нужен отдельный шлюз типа Mobizon).

Встроенная отправка почты Supabase сильно ограничена по объёму и часто попадает в спам — для реальных
клиентов надо подключить свой SMTP в Supabase → Project Settings → Auth → SMTP Settings. Проще всего —
завести аккаунт на Resend (он же нужен для писем о доступе выше) и туда же вписать его SMTP-данные.

## Что ещё не готово

- **Фото и видео.** Фото Эксперт уже стоит (`public/images/expert-hero.jpg`), но это заглушка
  из присланного файла — замените на финальное студийное фото при желании. Видео уроков — ссылки
  на YouTube нужно проставить в админке (Курстар мен сабақтар → сабақ → «YouTube видео сілтемесі»).
- **Загрузка файлов из админки.** Фото и материалы урока сейчас вставляются по прямой ссылке (URL),
  без формы загрузки. Для файлов — создайте public bucket в Supabase Storage и вставляйте ссылку
  оттуда (подсказка есть прямо в форме настроек).
- **Платёжный шлюз для карт** — см. «Оплата» выше, ждём выбор провайдера и юрлицо для регистрации.
- **Настоящая защита видео (не просто YouTube с убранным брендингом)** — см. «Как устроена защита» выше.
- **Настоящие push-уведомления о новостях** — сейчас только счётчик-колокольчик для тех, кто уже на сайте.
